A bouncer for your website.
The guests are robots.

CrawlBouncer is a free, open-source gateway that sits in front of your site and decides what each AI crawler is allowed to do: come in, or get turned away at the door.

Why does this exist?

AI companies send crawlers to read the web, and many of them don't ask first. If you write or publish anything online, you should get to choose who reads it.

Tools for this already exist, but they are mostly closed and run on someone else's servers, so you have to trust them. CrawlBouncer is the version you can read, change and host yourself. It is free, it was built to be shared, and contributions are welcome.

What is it?

A small web service (Python + SQLite, plus a React dashboard). Traffic for your domain passes through it. For every visitor it works out: human, ordinary bot, or a named AI crawler? Then it applies your rules.

RuleWhat the crawler sees
allowThe normal page. Come on in.
blockHTTP 403. Not tonight.

Rules can be set per crawler (GPTBot, ClaudeBot, PerplexityBot and friends) and per path (/blog/ open, /premium/ closed). It also comes with:

  • a web firewall (SQL injection, XSS and other classics), rate limiting, and traffic-flood detection
  • a dashboard showing who visited and what the bouncer did about it
  • a generated robots.txt that matches your rules
  • a "bolt-on" mode: keep your current setup and just ask CrawlBouncer for a decision (POST /v1/decide)
  • two-factor login, team members, and an audit log
Be realistic. This is early software. Crawlers are recognised by their User-Agent, and a determined scraper can fake that. It is a good bouncer, not a bank vault. See docs/KNOWN_LIMITATIONS.md in the repository.

How to set it up

The easy way uses Docker. You need nothing else.

  1. Get the code and enter the folder: 
    git clone https://github.com/nayan-mis/crawlbouncer.git
cd crawlbouncer
  2. Create your settings file and open it: 
    cp .env.example .env
    Set JWT_SECRET to a long random value (openssl rand -hex 32 makes one). Change ENV to production on a real server.
  3. Start it: 
    docker compose up -d --build
  4. Open /signup.html on that machine (http://localhost:8000/signup.html) and create your account. The first account becomes the admin; after that, signups are closed unless you allow them.
  5. In the dashboard, go to Domains → Add domain. Then choose how traffic reaches CrawlBouncer:
    • Reverse proxy: point your domain's DNS (a CNAME) at your CrawlBouncer server and give it your origin URL. Put Caddy in front for automatic HTTPS (a ready example is in deploy/Caddyfile.example).
    • Bolt-on: no DNS change. Your own server calls POST /v1/decide. Snippets are in integrations/bolt-on/.
  6. Open Crawlers, pick allow or block for each one, and press save. Done. The bouncer is on shift.

Without Docker

cd frontend && npm ci && npm run build && cd ..
cd backend && pip install -r requirements.txt
cp ../.env.example ../.env     # edit it, then:
python run.py

Needs Python 3.12 and Node 20. Then open http://localhost:8000.

Something not working?

Check docker compose logs crawlbouncer first. Emails (verification, password reset) are printed there too when SMTP isn't set up. Still stuck? Open an issue on the repository, with the log lines and what you expected to happen.
